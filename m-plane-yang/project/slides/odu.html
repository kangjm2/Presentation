(약 55초) 그럼 O-DU를 만드는 쪽에서는 YANG을 어떻게 활용할 수 있을까요. O-DU에게 YANG은 RU를 다루는 설계도이자 계약서입니다. 여섯 가지로 정리했습니다. 첫째, 코드 생성입니다. pyang이나 libyang 같은 도구로 YANG에서 데이터 구조와 파서, 검증 코드를 자동으로 만들어 손으로 XML을 다루는 일을 없앱니다. 둘째, 능력 기반 설정입니다. 연결된 RU의 yang-library와 module-cap을 읽고 RU마다 설정을 자동으로 맞추면, 벤더가 바뀌어도 같은 코드로 대응합니다. 셋째, 보내기 전에 같은 모델로 O-DU 안에서 먼저 검사해 오류를 미리 잡습니다. 넷째, candidate에 쓰고 검증한 뒤 commit하고, confirmed-commit으로 문제가 생기면 자동으로 되돌립니다. 다섯째, 경보, 동기, 캐리어 상태 알림을 구독해서 셀 정지나 재설정을 자동으로 처리합니다. 여섯째, 같은 모델로 만든 가상 RU로 연동 시험을 하고, 벤더별 deviation과 feature를 관리합니다. 계층형 구조라면 O-DU는 이렇게 모은 RU의 상태와 경보를 O1으로 SMO에 보고합니다.
