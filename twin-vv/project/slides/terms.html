V · Verification · 검증

제대로 만들었나 (built right)

모델 구현이 개발자의 개념 설명 · 명세를 정확히 나타내는지 정하는 과정
트윈: 솔버 · 코드 · 입력 변환 (4쪽)

V · Validation · 타당성 확인

맞는 모델인가 (right model)

의도한 용도의 관점에서 모델이 실제 세계를 얼마나 정확히 나타내는지 정하는 과정
트윈: DT 실측과 비교 (5~11쪽)

A · Accreditation · 인증

이 용도에 써도 되나

모델이 특정 목적에 쓰기에 받아들일 만하다는 공식 확인
트윈: 용도별 합격선 · 승인자 · 유효 기간 (13쪽)

보정(calibration) ≠ 확인

NASA-STD-7009A: 보정은 참조값에 더 맞도록 파라미터를 조정하는 것 (= tuning)
→ 보정에 쓴 자료로 확인하면 맞춘 것을 다시 재는 셈 (9쪽)

확인은 합격 · 불합격이 아니다

ASME V&V 20: 확인 = 모델 오차의 평가 (E = S − D와 그 구간)
→ 합격선은 용도가 정하고, 그 판단이 인증이다

나눔 검증은 만든 쪽이, 확인은 자료가, 인증은 쓰는 쪽(결정하는 사람)이 책임진다 — 셋을 한 숫자로 섞지 않는다

정의: DoD M&S 지시 (Youngblood · Pace 1995 인용) · 현행 DoDI 5000.61 (2024) · NASA-STD-7009A (2016) · Eça 외 2020

(약 55초) 시뮬레이션 분야에서는 세 질문을 나눠 묻습니다. 첫째 검증, verification은 제대로 만들었는가입니다. 미 국방부 정의로는 모델 구현이 개발자의 개념 설명과 명세를 정확히 나타내는지 정하는 과정입니다. 우리 트윈에서는 솔버와 코드, 입력 변환이 여기에 해당합니다. 둘째 타당성 확인, validation은 맞는 모델인가입니다. 의도한 용도의 관점에서 실제 세계를 얼마나 정확히 나타내는지 정하는 과정이고, 드라이브 테스트 비교가 여기입니다. 셋째 인증, accreditation은 이 용도에 써도 되는가에 대한 공식 확인입니다. 두 가지를 덧붙입니다. NASA 표준은 보정을 참조값에 더 맞도록 파라미터를 조정하는 것으로 정의합니다. 그래서 보정에 쓴 자료로 확인하면 맞춘 것을 다시 재는 셈이 됩니다. 또 ASME V&V 20은 확인을 합격, 불합격이 아니라 모델 오차의 평가로 봅니다. 합격선은 용도가 정하고, 그 판단이 인증입니다. 검증은 만든 쪽이, 확인은 자료가, 인증은 쓰는 쪽이 책임진다고 나눠 두면 정리가 됩니다.
