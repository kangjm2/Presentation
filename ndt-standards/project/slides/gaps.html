항목

표준이 말하는 것 (요약)

정하지 않은 것 → 다룰 곳

정확도 기준

Y.3090 “정확하고 실시간인 묘사” · Y.3091 모델 품질 “낮음 / 높음” · TS 28.561 “좋은 근사” · O-RAN “필요한 정확도에 이르면”

dB 숫자 · 지표 · 칸 크기가 없다
→ 합격선 정하기 (twin-vv)

전파 모델 충실도

ZSM 015 “전파는 시뮬레이션으로” · TS 28.561 전파 DT는 종속으로, 구현은 범위 밖 · O-RAN 레이 트레이싱 · 미분 RT 소개

엔진 · 재질 · 반사 차수 · 장면 해상도가 “충분한지” → twin-vv · ray-tracing

동기화

Y.3090 “허용 지연 범위 안에서” · Y.3091 갱신 주기 단계 (일 · 시간 · 분 · 초 · 실시간) · TS 28.561 수집 주기는 소비자가 조절

무엇을 (장면 · CM · 실측) 얼마나 자주
→ twin-data-sync

검증 방법

ZSM 015 입력 · 출력 데이터 정확도를 요청 · 보고 (권고) — 데이터 품질을 재고 검증하는 방법은 “추가 연구”

비교 절차 · 표본 · 판정
→ twin-vv · dt-breakdown

핵심 표준은 “정확해야 한다”까지 — 얼마나 정확해야 하고 어떻게 잴지는 용도가 정한다 (ZSM 015) → 그 숫자는 우리 몫

각 표준 문구는 요약 · 번역 (직접 인용 아님) · twin-vv · twin-data-sync는 같은 시리즈의 덱

(약 55초) 이 발표에서 가장 중요한 장입니다. 표준이 정하지 않고 비워 둔 것입니다. 첫째, 정확도 기준입니다. Y.3090은 정확하고 실시간인 묘사를, Y.3091은 모델 품질을 낮음과 높음으로, 3GPP는 좋은 근사를, O-RAN은 필요한 정확도에 이르면이라고만 씁니다. 몇 dB인지, 어떤 지표와 칸 크기로 잴지는 어디에도 없습니다. 둘째, 전파 모델 충실도입니다. ETSI는 전파를 시뮬레이션하라고만 하고, 3GPP는 구현을 범위 밖에 두며, O-RAN은 레이 트레이싱을 소개할 뿐입니다. 어떤 엔진과 재질, 반사 차수면 충분한지는 우리가 정합니다. 셋째, 동기화는 허용 지연 안에서, 갱신 주기 단계 같은 틀만 있고, 무엇을 얼마나 자주 갱신할지는 없습니다. 넷째, 검증 방법은 정확도를 요청하고 보고하는 기능만 권고하고, 재는 법은 추가 연구로 남겼습니다. 정확도와 검증은 twin-vv 덱에서, 동기화는 twin-data-sync 덱에서 이어서 다룹니다.
