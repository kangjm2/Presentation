목적 함수

목적 함수가 곧 정책이다

J = 커버리지% − λ · 겹침% # λ = 1 (예시)
커버리지% = 칸 비율 (1위 RSRP ≥ −105 dBm)
겹침% = 칸 비율 (1위 − 2위 ≤ 3 dB)
제약: 틸트 0 ~ 12° · 한 번에 바꾸는 셀 수 · 커버리지 ≥ 지금

무엇에 가중하나

면적 가중 (칸마다 같게) vs 트래픽 가중 (사람 · 데이터가 많은 칸을 크게) — 답이 달라질 수 있다

다른 항목

SINR 하위 5% · 셀 부하 최대값 · 불균형 · HO 실패율 — 사용 사례마다 고른다

기준값은 예시

−105 dBm · 3 dB · λ는 운영 정책 — 바꾸면 “최적”도 바뀐다 (10쪽 Pareto)

수치: 4쪽 예시 지역의 계산값 · 기준값(−105 dBm · 3 dB · λ = 1)은 예시이며 표준 값이 아님

(약 45초) 루프의 셋째 단계, 목적 함수는 사실상 운영 정책입니다. 예시에서는 커버리지 비율에서 겹침 비율을 뺀 J를 씁니다. 커버리지는 1위 RSRP가 −105 dBm 이상인 칸의 비율, 겹침은 1위와 2위가 3 dB 안에 있는 칸의 비율입니다. 기준 설정의 J는 53.8, 트윈이 찾은 최대는 59.6로 5.8 올랐고, 참고로 SINR 하위 5% 지점도 -0.8 dB에서 0.0 dB로 좋아졌습니다. 세 가지를 주의합니다. 칸마다 같은 무게를 줄지, 트래픽이 많은 칸에 더 줄지에 따라 답이 달라집니다. 사용 사례에 따라 부하나 핸드오버 실패율 같은 다른 항목을 씁니다. 그리고 −105 dBm, 3 dB, 가중치 1은 모두 예시입니다. 이 값을 바꾸면 최적도 바뀌는데, 이것은 10쪽에서 다시 봅니다.
