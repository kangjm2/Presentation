이득 단위는 보수적으로 읽고, 같은 패턴은 해시로 판정한다

파일

이득을 읽는 법

MSI

GAIN 숫자만 있으면 dBd로 읽는다 (+2.15 dB) · 줄에 dBi라고 적혀야 dBi

BASTA

Gain (dBi 또는 dBd), 없으면 EIRP − Configured_Output_Power

웨이트 파일

빔 레코드는 지향성 기준 (무손실) — 수준은 16쪽

왜 dBd가 기본인가

dBd 파일을 dBi로 잘못 짐작하면 모든 셀이 2.15 dB 과대 → 틀리더라도 덜 위험한 쪽을 기본으로

구분하지 않는 것

두 리더 모두 지향성(directivity)과 실현 이득(realised gain)을 나누지 않는다

physics_sha256 — 같은 패턴 판정

shape · reconstruction · vertical_positive · gain_dbi
horizontal_db · vertical_db · grid_att_db
기본값이 아닌 array.polarization · pol_grids

같은 해시 = 같은 풀이

해시가 같은 두 레코드는 똑같이 풀린다 → 이름이 달라도 물리는 같다 · 리비전(24쪽)이 이 해시를 기록한다

(약 45초) 보충 장입니다. MSI 파일에 GAIN 숫자만 있으면 CF는 dBd로 읽고 2.15 dB를 더합니다. 줄에 dBi라고 적혀 있을 때만 dBi로 읽습니다. 이유는 위험의 크기입니다. dBd 파일을 dBi로 잘못 짐작하면 모든 셀이 2.15 dB 과대가 되기 때문에, 틀리더라도 덜 위험한 쪽을 기본으로 했습니다. BASTA는 Gain 값을 쓰고, 없으면 EIRP에서 설정 출력 전력을 뺍니다. 두 리더 모두 지향성과 실현 이득을 구분하지 않고, 웨이트 파일에서 만든 빔 레코드는 무손실 지향성 기준입니다. 오른쪽은 같은 패턴인지 판정하는 방법입니다. 풀이에 영향을 주는 키들만 모아 해시를 만들고, 해시가 같은 두 레코드는 이름이 달라도 똑같이 풀립니다. 이 해시가 뒤에서 볼 리비전 기록의 바탕입니다.
