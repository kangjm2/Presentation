⑥ 보충 · 빔 레코드 vs 포트 레코드

빔 레코드 vs 포트 레코드 — 웨이트를 언제 곱하나

빔 레코드 <set>-b<k>

포트 레코드 <set>-port

담긴 것

빔 k의 완성 패턴: E · S · |AF(w_k)|², 편파 전력 합

포트 하나의 패턴: E · S (측정 파일이면 G_pol)

웨이트

이미 들어 있음 · 빔마다 레코드 하나

없음 · 세트에 레코드 하나

배열 이득

레코드 안에 이미 있음

없음 → 채널에 웨이트를 곱할 때 생긴다

솔버 배열

1×1 (소자 하나 = 빔 하나)

제 배열 4행 × 8열 × 편파 2 = 64

나오는 것

빔마다 라디오맵 레이어 (전력)

송신 안테나 64개 채널 H (포트별 크기 · 위상)

빔 만들기

끝나 있음

소비자가 H @ w (리포 안에는 테스트만)

편파 · 웨이트 바꾸기

편파 구분 없음 · 바꾸려면 다시 가져오기

포트별로 구분 · 같은 H에 다른 w만 곱하면 됨

주로 쓰는 곳

SSB 빔 레이어 → 빔별 SS-RSRP, 셀 = 최대

포트 단위 채널로 빔포밍 · 프리코딩을 직접 할 때

왜 배열 모양이 다른가

빔: 배열 이득이 이미 안에 → 64소자에 올리면 두 번 (BEAM_ARRAY)
포트: 소자 하나의 모양뿐 → 위치 위상은 솔버가 64개 실제 위치로 H에 (PORT_ARRAY)

결과는 같게 맞춰 있다

2026-11-11부터 같은 웨이트면 |H @ w|² = 빔 레코드 (dB까지, 19쪽) · Sionna LOS 강한 방향 0.5 dB 안

고르는 기준

정해진 빔의 전력만 → 빔 레코드
웨이트가 바뀜 · 사용자별 빔 · MU-MIMO · 위상 · 편파 → 포트 레코드

비유: 빔 레코드 = 완성된 요리 사진, 포트 레코드 = 재료(포트별 채널) — 레시피(웨이트)는 나중에 고른다

(약 55초) 보충 장으로 빔 레코드와 포트 레코드를 나란히 놓았습니다. 둘 다 같은 웨이트 파일에서 만들지만, 웨이트를 언제 곱하느냐가 다릅니다. 빔 레코드는 웨이트를 미리 곱해 완성한 빔 하나의 3D 패턴이고, 빔마다 하나씩 있습니다. 배열 이득이 이미 안에 있으니 1×1로 풀고, 결과는 빔마다 라디오맵 레이어 하나, 즉 전력입니다. 편파는 합쳐져 있고, 웨이트를 바꾸려면 다시 가져와야 합니다. 포트 레코드는 웨이트를 곱하기 전 포트 하나의 패턴입니다. 제 배열 64개에 올려 풀면 포트마다 크기와 위상을 가진 채널 H가 나오고, 빔은 소비자가 H 곱하기 w로 만듭니다. 같은 H에 다른 웨이트만 곱하면 되고 편파도 구분됩니다. 배열 모양이 다른 이유는 배열 이득을 두 번 넣지 않기 위해서입니다. 두 길의 결과는 같은 웨이트라면 dB까지 같도록 맞춰져 있습니다. 정해진 빔의 전력만 필요하면 빔 레코드, 웨이트가 바뀌거나 위상과 편파가 필요하면 포트 레코드를 씁니다. 비유하면 완성된 요리 사진과 재료의 차이입니다.
