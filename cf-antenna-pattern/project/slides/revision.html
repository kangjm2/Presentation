패턴이 바뀌면 캐시도 바뀐다 — pattern_rev

흐름

같은 id로
다른 패턴을 다시 가져옴

→

개정판 번호 +1
(pattern_rev)

→

빌드 요청에 번호 부착

→

job id(캐시 키)에 포함
→ 이전 결과 재사용 안 함

개정판 0

키에서 빠진다 → 예전 키는 바뀌지 않는다 (기존 캐시 유지)

키를 만든 뒤 패턴이 또 바뀌면

계산 시점에 오류로 막는다 — 다른 패턴으로 계산한 결과가 같은 키에 섞이지 않게

왜 중요한가

패턴 파일만 고치고 다시 돌렸는데 결과가 그대로라면? — 개정판 없이는 캐시가 옛 결과를 돌려준다

출처: CF 문서 §2 (개정판 pattern_rev)

04 / 20

(약 40초) 같은 id로 다른 패턴을 다시 가져오면 개정판 번호가 하나 올라갑니다. 빌드 요청에 이 번호가 붙고 job id, 즉 캐시 키에 들어가므로, 패턴 내용이 바뀌면 이전 계산 결과를 재사용하지 않습니다. 개정판 0은 키에서 빠지기 때문에 예전 키는 그대로 유지됩니다. 그리고 요청이 키로 만들어진 뒤에 패턴이 또 바뀌면 계산 시점에 오류로 막습니다. 다른 패턴으로 계산한 결과가 같은 키에 섞이지 않게 하려는 것입니다. 패턴 파일만 고치고 다시 돌렸는데 결과가 그대로인 상황을 막는 장치입니다.
