④ iperf3 구조

iperf3: 제어 연결 하나 + 데이터 스트림

UE
iperf3 -c (클라이언트)

트래픽 서버
iperf3 -s (포트 5201)

제어 연결 (TCP)

데이터 스트림

① UE가 서버에 제어 연결을 연다 → ② 시험 조건(-t · -u · -b · -R …)을 넘긴다 → ③ 데이터 스트림을 연다 → ④ 끝나면 양쪽 결과를 주고받는다

UE를 클라이언트로

단말은 보통 사설 주소 · NAT · 방화벽 뒤 → 바깥에서 단말로 연결을 열기 어렵다 → 단말이 열고 -R로 DL을 받는다

서버는 한 번에 한 시험

iperf3 -s 하나는 동시에 한 시험만 받는다 — 단말 여러 대면 포트(-p)를 나눠 서버를 여러 개

모드

옵션

데이터 방향 (UE가 클라이언트일 때)

기본

iperf3 -c 서버

UE → 서버 = UL

반대

iperf3 -c 서버 -R

서버 → UE = DL (연결은 UE가 연다)

양방향

iperf3 -c 서버 --bidir

UL · DL 동시 (iperf3 3.7부터)

iperf3 문서: 기본 포트 5201, -R = 서버가 보냄, -u여도 제어 연결은 TCP · --bidir: 3.7 릴리스 노트 (2019)

09 / 16

(약 50초) iperf3의 구조입니다. 서버에서 iperf3 -s를 띄우면 포트 5201에서 기다립니다. 단말에서 iperf3 -c로 서버에 접속하면 먼저 TCP 제어 연결이 열리고, 시험 시간이나 UDP 여부, 속도, 방향 같은 조건을 넘깁니다. 그다음 데이터 스트림을 열어 시험하고, 끝나면 양쪽 결과를 주고받습니다. 기본은 클라이언트가 보내므로 단말이 클라이언트면 UL 시험입니다. -R을 주면 서버가 보내서 DL 시험이 되고, --bidir는 양방향을 동시에 합니다. 단말을 클라이언트로 두는 이유는 단말이 보통 사설 주소나 NAT 뒤에 있어서 바깥에서 단말로 연결을 열기 어렵기 때문입니다. 서버 하나는 한 번에 한 시험만 받으니 단말이 여러 대면 포트를 나눠 서버를 여러 개 띄웁니다.
