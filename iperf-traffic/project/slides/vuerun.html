가상 UE · 실행

칸 안에서 트래픽을 일으킨다 — 명령과 주의

# 1) UE마다 칸 만들기
sudo ip netns add ue1
# 2) UE 실행 — TUN을 ue1 칸 안에 (srsUE 예)
sudo srsue ue.conf --gw.netns=ue1
# 3) 칸 안에서 확인 · 트래픽
sudo ip netns exec ue1 ip route
sudo ip netns exec ue1 ping -c 5 SRV
sudo ip netns exec ue1 curl -o /dev/null \
    -w '%{speed_download} %{time_total}\n' \
    http://SRV/100MB.bin
sudo ip netns exec ue1 iperf3 -c SRV -R -t 30

curl 결과 읽기

speed_download는 바이트/초 → ×8 = bit/s · time_total은 연결부터 끝까지 — 작은 파일이면 TCP 느린 시작이 대부분

(약 55초) 실제 명령입니다. 먼저 ip netns add로 UE 칸을 만들고, UE 프로그램을 실행할 때 그 칸 안에 TUN을 만들게 합니다. srsUE라면 gw.netns 설정입니다. 그다음부터는 모든 명령 앞에 ip netns exec ue1을 붙여 칸 안에서 실행합니다. 라우팅 표에서 기본 경로가 TUN인지 확인하고, ping, curl, iperf3를 돌립니다. curl은 -o로 받은 파일을 버리고 -w로 속도와 시간을 찍습니다. speed_download는 바이트 단위라서 8을 곱해야 비트입니다. 도구마다 TUN 이름이 다릅니다. srsUE와 OAI는 소프트웨어 PHY를 가상 무선이나 SDR로 돌리고, UERANSIM은 물리 계층 없이 무선을 흉내 냅니다. 그래서 가상 무선에서 나온 MCS나 BLER는 실제 채널 값이 아니고, 처리량 한계가 CPU일 수도 있습니다. 가상 UE는 기능, 시나리오, 부하 시험에 쓰고, 무선 성능은 실단말로 봅니다.
