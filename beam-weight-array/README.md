# 빔 웨이트 파일은 PlanarArray에 어떻게 매핑되나

벤더 빔 웨이트 파일이 CF 빌드에서 Sionna `PlanarArray`의 어레이 정보와 포트 패턴으로 바뀌는 과정을 정리한 자료입니다. 웨이트 파일에는 빔마다 포트별 복소수만 있고, 포트가 어디에 놓였는지와 포트 하나가 어떤 패턴을 내는지는 없습니다. CF가 이 빈칸을 **추론 · 피팅 · 가정**으로 채우는 방법과, 각 값을 얼마나 믿을 수 있는지를 다룹니다. 용어 설명을 자세히 넣었고, 따로 [`glossary.md`](glossary.md)에 용어집을 두었습니다.

다루는 내용은 다음과 같습니다.

- 전체 그림: 라이브러리 패턴 = PlanarArray의 소자 패턴, 계산 흐름(등록 · 어레이 · 방향 · 편파 · 리비전)
- 용어 ① 구조: 소자 · 서브어레이 · 포트 · 패널 · 편파 · 간격(λ 단위)
- 용어 ② 패턴과 빔: 패턴 · 어레이 팩터 · 웨이트 · 조향 · 빔 패턴 · HPBW · E-tilt · 그레이팅 로브 · 서브어레이 팩터 · 지향성 · 켤레
- 형식별 이득 계산(MSI · BASTA · 빔 · 포트)과 어레이 크기 강제, 이득 이중 계산
- 파일에 있는 것 vs PlanarArray가 필요한 것, 근거의 세 등급
- 어레이 정보: 펼친 순서 → 배치 추론(2 × 8 × 4) → 세로 축 → 세로 피치(2.84 λ, 2π 모호성 · 켤레)
- 포트 패턴 모델: 서브어레이(4소자 · 0.71 λ)가 그레이팅 로브를 누르는 원리, 소자 수평폭 피팅(87.8°), 지향성 정규화
- PlanarArray로 들어가는 값(Sionna의 “소자” = 실제 포트), 신뢰도 표, geometry 덮어쓰기와 받아야 할 자료

참고할 점:
- **출처:** 계산 흐름, 형식별 이득, 포트 추정 규칙, 샘플 결과(2 × 8 × 4 · 2.84 λ · 4소자 0.71 λ · 87.8° · array 값), 제품팀 값(0.541 λ · 4 × 0.712 = 2.848 λ · 4개), 코드 위치(antenna_sionna.py · simulator.py · beam_weights.py의 줄 번호)는 모두 받은 CF 문서를 옮긴 것이고 코드와 대조하지는 않았습니다.
- **펼친 순서(7쪽):** 문서의 “편파 → 열 → 행, 위에서 아래”를 바깥 → 안쪽(행이 가장 빨리 바뀜)으로 읽어 n = (p · 8 + c) · 4 + r로 썼습니다. 이 해석은 **확인 필요**입니다.
- **합성 예시(7 ~ 12쪽, 생성기에서 numpy로 계산, 시드 고정):**
  - 웨이트: 2 × 8 × 4, d_h 0.5 λ, d_v 2.84 λ, 틸트 6°, 빔 8개(방위 −52.5° ~ +52.5°, 15° 간격), 편파마다 빔별 무작위 위상 오프셋, 위상 잡음 3°.
  - 배치 추론(8쪽)의 척도는 “위상 차의 흩어짐 = 1 − |단위 위상자 평균|”로 제가 정한 것입니다. CF 코드의 실제 기준식은 확인이 필요합니다. 결과: 2 × 8 × 4가 0.005, 다음 후보 0.07 이상.
  - 세로 위상 간격 약 106.7° → d_v ≈ 2.84 λ, 다음 해 12.4 λ(간격 9.57 λ).
  - 그레이팅 로브(11쪽): 앙각 +14°, −27°, +37°, −54°. 서브어레이 길이 = 포트 피치라 널이 같은 자리에 와서 곱은 −44 dB 이하.
  - 소자 수평폭 피팅(12쪽): 합성 SSB 웨이트(이웃한 두 열, 크기 1 : 0.25)로 약 108°. 문서의 샘플 결과 87.8°와 다른 것은 웨이트가 다르기 때문입니다.
  - 포트 패턴 지향성(13쪽): 수평폭 87.8° · 수직폭 65° · 4소자 0.71 λ · 6°로 약 13.6 dBi. 문서는 이 값을 밝히지 않았으므로 예시입니다.
- **켤레 · 좌우반전 설명(용어집 8절):** 송신 · 수신 기준에 따라 부호가 뒤집힐 수 있다는 설명은 일반적인 원리로 덧붙인 것입니다.
- **λ 환산:** 3.5 GHz는 환산 예로 든 값이며 문서의 대역이 아닙니다.
