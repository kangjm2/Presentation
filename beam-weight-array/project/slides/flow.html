라이브러리 패턴 = PlanarArray의 소자 패턴

② 어레이

→

③ 방향
방위각 · 기계 틸트
→ orientation

→

④ 편파

V · cross, tr38901_2

→

⑤ 리비전 확인
요청 뒤 패턴이 바뀌면
거절

핵심 빔 패턴 = 소자(포트) 패턴 × 어레이 팩터 — rows · cols가 1보다 크면 패턴 위에 어레이 팩터가 한 번 더 곱해진다

재등록

워커가 계산할 때마다 레코드를 다시 등록 → 패턴을 다시 가져오면 재시작 없이 반영

방향은 회전으로

패턴은 소자 좌표계 기준 · 방위각과 기계 틸트만 회전에 · 전기 틸트는 파일 패턴에 이미 들어 있다

오늘의 질문

웨이트 파일에는 rows · cols · 간격 · 패턴이 없다 → 이 다섯 칸을 무엇으로 채우나

(약 45초) 먼저 전체 그림입니다. 섹터가 라이브러리 패턴을 고르면, 계산할 때 워커가 그 레코드를 Sionna에 등록합니다. 그 다음 PlanarArray를 만드는데, 행과 열, 간격, 패턴 이름, 편파를 넣습니다. 이때 라이브러리 패턴은 어레이를 이루는 소자 하나하나의 패턴이 됩니다. 섹터의 방위각과 기계 틸트는 송신기 방향으로 들어가 패턴을 돌리고, 편파는 PolarizedAntennaPattern으로 감싸 적용합니다. 요청을 만든 뒤 같은 id의 패턴이 바뀌면 계산을 거절합니다. 핵심은 가운데 줄입니다. 빔 패턴은 소자 패턴 곱하기 어레이 팩터라서, 행이나 열이 1보다 크면 패턴 위에 어레이 팩터가 한 번 더 곱해집니다. 그런데 웨이트 파일에는 PlanarArray가 필요로 하는 행, 열, 간격, 패턴이 들어 있지 않습니다. 오늘은 이 빈칸을 어떻게 채우는지를 봅니다.
